# Simulated Interviews — Methodology

## What this is and why it exists

We don't yet have access to real growers to interview. Rather than leave
every persona's behavioural claims as untested `[VALIDATE]` guesses
indefinitely, this project uses **AI-simulated interviews**: a persona,
grounded in the real sources logged in `research/sources.md`, role-played
through the question set in `research/interview-guide.md` to produce a
plausible, internally consistent transcript.

This is a direct application of the source thesis's own idea (README task
#7 / the original conversation): *"AI could potentially change [research]
methodology... there may be an opportunity for situational AI analysis of
Australian farmers, using simulated personas and scenarios."* This file is
that method, made concrete and repeatable.

## What a simulated interview is good for

- **Stress-testing the framework** — does the journey spine, friction
  table, and opportunity card structure actually hold up when populated
  with a plausible, detailed answer, or does it break down somewhere?
- **Surfacing sharper hypotheses** — a simulated answer to "who's your most
  trusted advisor?" is a specific, falsifiable claim ("my stock agent, not
  a vet, because...") that's easier to walk into a real interview and
  confirm or knock down than an abstract `[VALIDATE]` tag.
- **Prioritising what to ask first** — if a simulated transcript exposes an
  internal tension or a place the persona's own logic breaks down, that's
  a strong candidate for the first question in a real interview.

## What it is emphatically NOT good for

- **It is not evidence.** A simulated transcript is a hypothesis-generation
  tool, not data. It must never be cited as if it were a real grower's
  words, never averaged into an economics model, and never used as the
  sole basis for a go/no-go decision on an opportunity.
- **It cannot surface what the framework doesn't already anticipate.** By
  construction, a simulated grower can only be as perceptive as the
  sources and persona file feeding it — it can sharpen an existing
  hypothesis, but it can't discover a friction point nobody has thought to
  ask about yet. Real interviews are the only way to find the unknown
  unknowns.
- **It inherits every gap and bias already in the persona file.** If the
  persona's `[VALIDATE]` tags are wrong, the simulated interview will
  confidently reproduce that wrongness in a more convincing voice, which
  is precisely the risk of overtrusting synthetic data. That's why every
  transcript in `research/interviews/` carries the same "SIMULATED" banner
  and confidence rating as everything else.

## Confidence tier

Add this to the confidence key in `research/sources.md`:

- **Simulated (synthetic)** — an AI-generated transcript grounded in
  logged sources but not from a real person. Ranks *below*
  secondary/commentary in evidentiary weight; treat every claim in one as
  a hypothesis to validate, exactly like an ungrounded `[VALIDATE]` tag,
  just a more specific one.

## Process (repeatable per persona)

1. Read the target persona file (`personas/*.md`) and its journey file
   (`journeys/*.md`), including every `[VALIDATE]` tag — these are exactly
   the gaps the simulation should try to fill in a plausible, specific way.
2. Construct the simulated grower's specific situation (name, property
   type/size, region, season conditions) — concrete enough to answer
   specifically, but explicitly invented, never modelled on a real,
   identifiable individual or operation.
3. Role-play through `research/interview-guide.md` in full, including the
   agronomist/advisor companion questions where relevant, staying
   consistent with everything already known/sourced about the persona and
   inventing plausible specifics only where the persona file has a genuine
   gap.
4. Write the result to `research/interviews/<persona>-simulated-NN.md`
   with the standard banner (see template below).
5. Go back to the persona and journey files: where the simulated interview
   gives a specific, plausible answer to a `[VALIDATE]` question, don't
   delete the tag — annotate it as informed by a simulated interview
   (cite the file) while keeping it clearly below real-interview
   confidence, and note explicitly what a real interview would need to
   confirm or overturn.
6. Track disagreements between multiple simulated passes (if more than one
   is run for the same persona) — where they diverge is itself a signal of
   which questions are most likely to be genuinely uncertain rather than
   the model's own consistent bias.

## Required banner for every file in `research/interviews/`

```
> ⚠️ SIMULATED INTERVIEW — NOT A REAL GROWER. Generated by AI role-play
> against a persona file, per `research/simulated-interview-methodology.md`.
> Confidence tier: Simulated (synthetic) — below secondary/commentary in
> `research/sources.md`. Every claim here is a hypothesis to test in a
> real interview, not a finding. Do not cite this file as evidence in any
> economics model, adoption claim, or external-facing material.
```
